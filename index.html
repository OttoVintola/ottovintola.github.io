__global__ void transform(
    const int* A, int* B, int N) {
  int col = blockIdx.x * blockDim.x + threadIdx.x;
  int row = blockIdx.y * blockDim.y + threadIdx.y;
  if (row < N && col < N) {
    int idx = row * N + col;
    B[idx] = A[idx] * 2 + 1;
  }
}

How This Simulation Works

GPU Architecture Concepts

  • Streaming Multiprocessors (SMs): Independent processing units on the GPU. Each SM can execute multiple thread blocks. Configured: 2 SMs.
  • Warp Schedulers: Each SM has multiple warp schedulers that can issue instructions to warps each cycle. Configured: 2 per SM.
  • Warps: Groups of 32 threads that execute in SIMT (Single Instruction, Multiple Threads) fashion. All threads in a warp execute the same instruction simultaneously.
  • Thread Blocks: Logical groupings of threads. Each block is assigned to one SM and cannot migrate. Block size: 4×4 = 16 threads.

Cycle-Accurate Execution Model

  • Each cycle: Every warp scheduler in every active SM can execute one warp (up to 32 threads).
  • Block assignment: Blocks are assigned to SMs in round-robin fashion. An SM processes all warps in its assigned blocks before getting new ones.
  • Warp formation: Threads within a block are grouped into warps of 32. A 4×4 block (16 threads) = 1 warp. An 8×8 block (64 threads) = 2 warps.
  • Parallel execution: With 2 SMs × 2 warp schedulers = 4 warps can execute per cycle = up to 128 threads.
Note: This is a simplified model. Real GPUs have additional complexities: memory latency hiding, occupancy limits, shared memory constraints, register pressure, and instruction-level parallelism within warps.

What You're Seeing

  • Matrix cells turn red: Threads are currently executing the computation for those elements.
  • SM panel shows active warps: Each small square represents a thread slot; red = executing this cycle.
  • Grid shows block status: Which blocks are assigned to SMs and their completion state.
